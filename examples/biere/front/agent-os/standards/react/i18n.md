# i18n — no hardcoded user-facing strings

Every string a user can read renders through `t(...)` (react-i18next). A literal display
string in a component is a bug, even in English: titles, labels, button text, placeholders,
empty states, `aria-label`s, `sr-only` text, option labels (`ListBox.Item` text and
`textValue`), toasts and error messages.

```tsx
// WRONG — hardcoded, and French on top
<Label>Utilisateur courant</Label>

// RIGHT
const { t } = useTranslation();
<Label>{t("pages.profile.demoUser.label")}</Label>
```

- i18n is initialised in `src/i18n/i18n.ts`: `fr` is the default language, `en` the
  fallback. Outside React (a service, `DisplayError`) use `i18n.t(...)` from that module.
- Keys live in **both** bundles, `src/i18n/locales/fr.json` and `src/i18n/locales/en.json`
  (list the folder, do not trust this sentence), mirrored: every key exists in every file,
  with a real translation, added in the same commit.
- `src/__tests__/i18n/localesParity.test.ts` enforces key parity and non-empty values. It
  is a targeted gate for any change touching a locale file: run it, and never classify its
  red as pre-existing when your diff adds keys.
- Reuse an existing key before adding one; key paths mirror the feature
  (`pages.<feature>.<thing>`, `nav.<tab>`, `errors.<case>`).
- Plurals use i18next suffixes (`tastingCount_one`, `tastingCount_other`) with `{{count}}`;
  never concatenate a number with a word.
- Copy is written to survive a 360px screen: short labels, no layout that depends on the
  French length (see `ui/mobile-first`).

## Verbatim exceptions — keep literal, do NOT wrap in t()

Same boundary as `naming-language`: a string that must equal something a backend or a
browser already knows is data, not copy.

| Kind | Example |
|------|---------|
| Route URL segment | `RoutePathEnum.MAP = "/carte"` |
| Storage key | `StorageKeyEnum.CURRENT_USER_ID = "mousse.currentUserId"` |
| API-returned business label | a beer `name` / `style` value the API emits (render as-is) |

Rule of thumb: if you authored the string for a human to read, it is a `t(...)` key. If it
must match an external contract, it stays verbatim.
